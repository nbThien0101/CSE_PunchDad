# CSE HitDad 1.2.4

Ngày cập nhật: **17/10/2026**. Bản này tập trung vào xác thực tài khoản, quản lý phiên, OTP và cập nhật nhận diện CSE HitDad.

Tài liệu mô tả bản mã nguồn 1.2.4. Việc nâng số version trong repository không xác nhận production đã được deploy. Báo cáo kiểm tra sự cố nằm tại [security audit 17/10/2026](../security-audit-2026-10-17.md); nguyên nhân của lần truy cập trái phép được báo cáo vẫn cần đối chiếu cấu hình và log production.

## Thay đổi chính

| Trước 1.2.4 | Hành vi trong 1.2.4 |
| --- | --- |
| Cấu hình có thể dùng khóa ký JWT mẫu hoặc hai khóa trùng nhau | Server từ chối khởi động nếu khóa thiếu, ngắn hơn 32 ký tự, khớp mẫu bị cấm hoặc hai khóa trùng nhau |
| Token chỉ gắn user ID và thời hạn, không có cơ chế thu hồi theo mật khẩu | Token có `authVersion` và `tokenType`; backend chỉ nhận HS256, đúng loại token và đúng phiên bản trong DB |
| Đổi/reset mật khẩu vẫn để token cũ hoạt động | Tăng `User.authVersion`; mọi access/refresh token cũ bị từ chối, gồm cả phiên đang đổi mật khẩu |
| Refresh không tra lại user trong DB | Refresh xác nhận user còn tồn tại và phiên bản khớp trước khi cấp token mới |
| Access token mặc định 7 ngày | Mặc định 15 phút; refresh mặc định 30 ngày. Biến môi trường có thể ghi đè các thời hạn này |
| OTP đầu vào đăng ký có thể được nhận như một bộ lọc truy vấn | Chỉ nhận chuỗi sáu chữ số; phân biệt mục đích đăng ký và khôi phục |
| Giới hạn đoán OTP chủ yếu theo IP | Thêm giới hạn tối đa năm lần thử cho mỗi challenge, lưu trong DB |
| Một mã/proof có thể được đọc và dùng đồng thời | Transaction cùng cập nhật có điều kiện bảo đảm chỉ một request tiêu thụ thành công cùng mã/proof |
| Script demo có thể chạy với cấu hình production | Hai script seed demo từ chối chạy khi `NODE_ENV=production` |

Nhận diện giao diện được cập nhật ở logo, favicon, banner, tên ứng dụng, màn hình xác thực, email, thanh toán và phản hồi. Footer hiển thị `v1.2.4`; version trong ba package manifest và ba lockfile đã đồng bộ.

README cũng được viết lại để phản ánh tính năng hiện có: thành viên đề xuất khung giờ, quản trị phản hồi, điểm danh/khách mời và các route API thật. Đây là cập nhật tài liệu cho các chức năng đã có trong source, không đồng nghĩa tất cả chức năng đó được thêm mới ở 1.2.4.

## Ảnh hưởng tới người dùng

- Sau khi backend chạy 1.2.4, token cấp trước bản vá không còn hợp lệ; người dùng phải đăng nhập lại.
- Migration đánh dấu các OTP, verification proof và reset proof chưa dùng trước nâng cấp là đã dùng. Luồng đăng ký/quên mật khẩu đang dở phải bắt đầu lại bằng mã mới.
- Đổi mật khẩu tại trang hồ sơ đưa phiên hiện tại về trạng thái đăng xuất. Các thiết bị khác mất quyền truy cập ở lần xác thực/refresh tiếp theo.
- Mỗi OTP chỉ thử tối đa năm lần và chỉ chấp nhận mã mới nhất của cùng mục đích. Khi hết lượt hoặc hết hạn, người dùng yêu cầu mã mới theo giới hạn gửi lại.
- Migration bảo mật không xóa tài khoản, trận đấu, vote hoặc khoản thanh toán; không tự đổi mật khẩu và không khôi phục thông tin từng bị sửa trái phép.

## Migration và tương thích

Migration mới: [`20261017090000_harden_auth_sessions`](../../server/prisma/migrations/20261017090000_harden_auth_sessions/migration.sql).

| Bảng | Thay đổi |
| --- | --- |
| `users` | Thêm `auth_version INTEGER NOT NULL DEFAULT 0` |
| `otp_verifications` | Thêm `attempts INTEGER NOT NULL DEFAULT 0` |
| `otp_verifications` | Đặt `used=true` trên mọi bản ghi chưa dùng ở thời điểm migration |

Prisma Client phải được generate từ schema mới. Không chạy backend 1.2.4 với DB chưa có migration. Nếu môi trường còn thiếu migration cũ, `prisma migrate deploy` sẽ áp dụng theo thứ tự, gồm bảng phản hồi của migration `20261001160000_add_feedback` nếu chưa có.

Các API khôi phục mật khẩu chính xác là:

```text
POST /api/auth/forgot-password/send-otp
POST /api/auth/forgot-password/verify-otp
POST /api/auth/forgot-password/reset
```

Client tiếp tục gửi OTP như một chuỗi và dùng proof trả về từ server. Client không tự chọn `authVersion` để đăng nhập. Không có endpoint mới cho đăng xuất: nút đăng xuất xóa token trong trình duyệt; thu hồi mọi phiên phía server xảy ra khi đổi/reset mật khẩu hoặc thay khóa ký.

## Quy trình nâng cấp production

### 1. Chuẩn bị bản triển khai

- Đảm bảo commit sẽ deploy đã chứa bản vá, migration, schema và version 1.2.4. Chỉ bấm deploy code cũ trên GitHub sẽ không đưa bản sửa local lên server.
- Nếu đang xử lý sự cố, tạm ngưng frontend và API trong lúc chuẩn bị. Giữ lại thời điểm, ảnh chụp và log cần đối chiếu.
- Có bản sao lưu DB trước khi áp dụng migration; xác nhận `DATABASE_URL` thuộc đúng môi trường.
- Dùng Node.js 22.12 trở lên cho toolchain hiện tại; môi trường đã kiểm thử dùng Node 24.

### 2. Đặt hai khóa JWT mới trên Render

Chạy lệnh sau **hai lần trên máy**, mỗi kết quả dùng cho một biến khác nhau:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Cập nhật môi trường backend:

```env
JWT_SECRET=<gia-tri-ngau-nhien-thu-nhat>
JWT_REFRESH_SECRET=<gia-tri-ngau-nhien-thu-hai>
JWT_EXPIRES_IN=15m
JWT_REFRESH_EXPIRES_IN=30d
NODE_ENV=production
CLIENT_URL=https://<ten-mien-frontend>
```

Giữ các giá trị thật ở hệ thống cấu hình môi trường. Không commit hoặc gửi chúng qua chat. `generateValue: true` trong `render.yaml` không thay thế thao tác đổi khóa đã tồn tại. Nếu lưu cấu hình trước lúc code sẵn sàng, chỉ lưu và thực hiện deploy sau khi đủ bản vá.

### 3. Deploy backend kèm migration

Cấu hình dự án trong `render.yaml`:

```text
Root directory: server
Build command: npm install && npx prisma generate
Start command: npx prisma migrate deploy && node src/app.js
```

Nếu chạy thủ công trong môi trường đã đặt biến đúng:

```bash
cd server
npm ci
npx prisma generate
npx prisma migrate deploy
npm start
```

Kiểm tra log có migration thành công, không có lỗi schema hoặc lỗi cấu hình JWT, rồi kiểm tra `GET /api/health`. Health check xác nhận tiến trình đang chạy; vẫn cần kiểm tra đăng nhập và OTP ở bước nghiệm thu.

### 4. Deploy frontend

```text
Root directory: client
Build command: npm run build
Output directory: dist
VITE_API_URL: https://<ten-api>.onrender.com/api
```

Vite nhúng biến môi trường lúc build; thay `VITE_API_URL` cần build/deploy lại. Đảm bảo `CLIENT_URL` ở backend khớp origin frontend. Cấu hình rewrite SPA có trong `client/vercel.json`.

### 5. Nghiệm thu trước khi mở lại

1. Đăng nhập mới bằng tài khoản kiểm thử; đối chiếu `/api/auth/me` trả đúng người dùng.
2. Dùng phiên cũ có sẵn trước nâng cấp: API từ chối, giao diện yêu cầu đăng nhập lại.
3. Đăng nhập tài khoản kiểm thử trên hai trình duyệt; đổi mật khẩu ở một nơi. Cả token access và refresh trước đó phải bị từ chối ở nơi còn lại.
4. Thử đăng ký và quên mật khẩu bằng email kiểm thử. Mã hết hạn, dùng lại, khác email hoặc sai mục đích phải bị từ chối.
5. Kiểm tra thành viên thường không có quyền quản trị, cập nhật hồ sơ chỉ tác động chính tài khoản đó.
6. Đối chiếu các thông tin tài khoản/QR bị báo sửa; kiểm tra tài khoản admin/demo và thay mật khẩu nếu còn dùng mật khẩu demo.
7. Mở lại dịch vụ sau khi các kiểm tra phù hợp; tiếp tục đối chiếu log để xác minh phạm vi sự cố.

Nếu cần khắc phục một lần deploy thất bại, giữ khóa mới và dữ liệu đã sao lưu, xác định lỗi cụ thể rồi sửa tiếp. Đưa lại backend cũ có thể khôi phục cơ chế xác thực dễ bị ảnh hưởng trước bản vá.

## Kiểm thử bản phát hành

Các kiểm tra không cần DB, chạy từ thư mục gốc:

```bash
npm --prefix server test
npm --prefix client run build
```

Lệnh test backend chạy hai nhóm kiểm tra JWT; nhóm PostgreSQL bị skip nếu không đặt biến riêng. Để chạy đủ integration test, tạo DB riêng `cse_punchdad_auth_security` trên localhost rồi chạy trong `server` (URL bên dưới là ví dụ cho DB test tạm):

```bash
DATABASE_URL='postgresql://auth_test@127.0.0.1:55439/cse_punchdad_auth_security' npx prisma migrate deploy
AUTH_SECURITY_TEST_DATABASE_URL='postgresql://auth_test@127.0.0.1:55439/cse_punchdad_auth_security' npm test
```

Bộ test từ chối host ngoài loopback và tên DB ngoài `cse_punchdad_auth_security`, dùng tài khoản giả và vô hiệu hóa email. Không trỏ các lệnh này vào DB production.

Kết quả kiểm chứng bản vá ngày 17/10/2026:

| Kiểm tra | Kết quả |
| --- | --- |
| JWT + controller/middleware với Prisma trên PostgreSQL tạm 18.3 | 17 test đạt, không skip |
| Áp dụng toàn bộ migration lên DB thử nghiệm mới | Thành công |
| Generate Prisma Client và validate schema | Thành công |
| Build frontend | Thành công |

Các test kiểm tra token bị sửa ID/chữ ký, token sai loại/cũ, phân quyền hồ sơ, OTP sai kiểu, ràng buộc email/mục đích, hết hạn/hết lượt, tranh chấp request, thu hồi access/refresh sau đổi/reset mật khẩu và user đã bị xóa. Kết quả này không chứng minh production đã cập nhật hoặc xác nhận được lịch sử xâm nhập.
